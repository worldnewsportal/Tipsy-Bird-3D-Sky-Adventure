# دليل ربط Unity Ads (محدَّث 2026/2027)

اللعبة جاهزة بالكامل من جهة الويب (JS)، والجزء الأصلي (الأندرويد) الخاص بالإعلانات **مدمج في المستودع ويُحقن تلقائياً أثناء البناء في GitHub Actions — لا يوجد أي خطوة يدوية ولا حاجة لـ Android Studio.**

## الوضع الحالي لـ Unity Ads (مهم)

- **حزمة Unity القديمة داخل المحرر (Advertisement Legacy)**: منذ 1 أبريل 2026 أداؤها منخفض — لا نستخدمها.
- **Unity Ads Android SDK المباشر**: مدعوم ونشط — أحدث إصدار **4.22.0** (تحسينات تهيئة أسرع وحمولات أضمن). **هذا ما نستخدمه**.
- **Unity LevelPlay**: منصة وساطة لجمع شبكات إعلانية متعددة — اختيارية لاحقاً إن أردت AdMob/Meta في نفس اللعبة. ليست مطلوبة الآن.

## الخطوة 1: من لوحة Unity (مرة واحدة)

1. [dash.unity3d.com](https://dash.unity3d.com) → **Monetization → Projects → Add new project**
2. اكتب اسم المشروع و الحزمة نفسها الموجودة في `android/app/build.gradle` (applicationId)
3. **Monetization Setup → Android** → **Game ID (Android)** — لعبتك: `800443610` (أُضيف في الكود مسبقاً)
4. فعّل **Test mode** في البداية حتى تتحقق، وأوقفه قبل رفع الإصدار النهائي للنشر
5. الخانات الجاهزة تكفي: `Rewarded_Android`, `Interstitial_Android`, `Banner_Android`

## الخطوة 2: الإضافة الأصلية — تلقائية 100% عبر GitHub Actions (بلا كمبيوتر)

كل ما يتطلبه ربط الإعلانات الأصلي تم تجهيزه في المستودع:

- **كود المكوّن الاصلي**: `native/UnityAdsPlugin.java` — Game ID `800443610` مدمج فيه، ويوفر الإعلانات الثلاثة: مكافآت (Rewarded) + بينية (Interstitial) + بانر (Banner).
- **سكربت الحقن**: `native/inject_native.sh` — يعمل تلقائياً في كل بناء.
- **ملف البناء** `.github/workflows/android.yml` يفعل عند كل تشغيل:
  1. نسخ `UnityAdsPlugin.java` إلى حزمة التطبيق `com.tipsybird.game`
  2. إضافة تبعية `implementation 'com.unity3d.ads:unity-ads:4.22.0'` إلى `android/app/build.gradle`
  3. تسجيل `registerPlugin(UnityAdsPlugin.class)` في `MainActivity.java`
  4. التحقق من الخطوات الثلاث وفشل البناء فوراً إن نقص أي منها

### ماذا تفعل أنت (من هاتفك فقط)

1. افتح المستودع في تطبيق/موقع GitHub ← تبويب **Actions**
2. اختر **Build Android APK** ← زر **Run workflow** ← **Run**
3. عند انتهاء البناء (أخضر ✓) نزّل الملف `TipsyBird3D-apk` وثبّته على هاتفك
4. الإعلانات ستعمل تلقائياً داخل الـ APK من أول تشغيل

> وضع الاختبار: افتراضياً **إنتاج** (وليس test). للتجربة الأولية يمكنك تشغيل وضع الاختبار من لوحة Unity Dashboard (Test mode toggle) دون كود.

## الخطوة 3: كيف تتأكد أن الإعلانات تعمل؟

بعد ربط الإضافة، ادخل اللعبة:

- **الإعدادات ← حالة الإعلانات** تعرض حالة Unity وبيانات تشخيص البانر. زر **اختبار** يختبر الإعلان المكافئ، وليس البانر.
- **الإعلان البيني** (interstitial): أنهِ 4 جولات كاملة دون إحياء — في نهاية الجولة الرابعة يظهر تلقائياً.
- **البانر**: طبقة Android ثابتة أسفل اللعبة، تبقى فوق القائمة واللعب والمتجر والإعدادات والعوالم والمهام. لا تخفيه تغييرات الصفحات أو إيقاف اللعبة مؤقتًا، ويُعاد إرفاقه بعد استئناف التطبيق.

قبل ربط الإضافة: تظهر "غير مرتبطة" ولا يظهر شريط إعلان. عند فشل التحميل أو `no fill` تبقى مساحة البانر محجوزة وتُعاد المحاولة؛ لكن لا يستطيع التطبيق إجبار Unity على توفير إعلان عندما لا يوجد مخزون أو عندما يكون موضع `Banner_Android` غير مفعّل.

## الوضع المتصل/غير المتصل (online/offline) — مدمج تلقائياً

اللعبة تعمل 100% بدون إنترنت، بينما تعمل الإعلانات فقط عند توفر الاتصال — والتبديل بين الحالتين **تلقائي بالكامل**:

| الحالة | ما تراه في الإعدادات | ما يحدث |
|---|---|---|
| متصل + مكوّن مربوط | **متصل — جاهزة ✓** ثم **مفعّلة ✓** | التهيئة تُنجز، ويُطلب البانر على كل صفحات اللعبة، والإعلان المكافئ/البيني محمّلان مسبقاً (preload) |
| قطع الاتصال أثناء اللعب | **غير متصل — الإعلانات بالإنترنت** | أزرار الإعلانات الاختيارية تخفى. البانر لا يُزال من الواجهة، لكن قد يبقى فارغًا إلى أن يتوفر اتصال وإعلان |
| عودة الاتصال | **متصل — جاهزة ✓** | تُعاد التهيئة تلقائياً وتستمر محاولة تحميل البانر؛ العرض الفعلي يعتمد على توفر إعلان من Unity |
| فتح التطبيق وأنت أوفلاين | **غير متصل** | التهيئة لا تُنفَّذ (لا خطأ ولا تعليق)، ثم تتم تلقائياً فور أول اتصال |
| معطّلة من الإعدادات | **معطّلة (الإعدادات)** | لا شيء إعلاني مهما كانت الشبكة |

تفاصيل تقنية مبنية في الكود:
- `showBanner` طلب مستمر مستقل عن مفتاح تشغيل الإعلانات الاختيارية وعن تغيّر صفحات اللعبة. طلب JavaScript idempotent حتى لا يكرر التحميل مع كل تغيير شاشة.
- طبقة Android واحدة تثبت فوق WebView، وتُرفع إلى مقدمة عرض Android، وتُفحص دوريًا. إذا انفصلت بعد إعادة إنشاء النشاط يعاد إرفاقها، وإذا لم يرد SDK على التحميل تعاد المحاولة.
- مستمعا `online`/`offline` + فحص عند **عودة التطبيق للمقدمة** (visibilitychange) + فحص وقائي كل 30 ثانية.
- **تحميل مسبق (preload)**: بعد نجاح التهيئة يحمّل الإعلان المكافئ والبيني في الخلفية، فتظهر الإعلانات فور الضغط بدل انتظار 5–10 ثوانٍ.
- إعادة التهيئة تحدث فقط إذا لم تكن الكلمة جاهزة `!UA.ready` — لا إعادة تهيئة زائدة.
- اللعبة نفسها (كل شيء ما عدا الإعلانات) تعمل أوفلاين 100% كماهي دائماً.

## أزرار مشاهدة إعلان (Rewarded) في اللعبة

| الزر | مكانه | المكافأة | التهدئة |
|---|---|---|---|
| **هدية 🎁** | القائمة الرئيسية | +15 🪙 | 3 دقائق بين كل إعلان |
| **+15 عملات 🎁** | أعلى المتجر (بجانب رصيد العملات) | +15 🪙 | نفس التهدئة المشتركة 3 دقائق |
| **استمرار 🎁** | شاشة الموت — خياران: ادفع 25 🪙 **أو** شاهد إعلان | إحياء مجاني فوري | لا تهدئة (يعتمد على توفر الإعلان) |

سلوك ذكي وأنيق:
- **لا يوجد إعلان الآن (no-fill)**: رسالة ودّية "لا يوجد إعلان الآن — حاول بعد قليل" فورًا — لا انتظار ولا تعليق — وتبقى العملات والتهدئة كما هي، والزر يظل متاحًا لإعادة المحاولة.
- **عند الموت**: خياران واضحان معًا — زر "تابع · 25 🪙" وزر "استمرار 🎁" (مشاهدة إعلان) — والمكوّن الأصلي يعيد `{failed:true}` عند فشل التحميل/العرض فيظهر نفس الرسالة الودّية بدل رسالة عامة.
- **إعادة التحميل بعد النجاح فقط**: بعد عرض إعلان ناجح يُعاد تحميل الإعلان التالي مسبقًا (preload) بعد 1.5 ثانية؛ عند الفشل لا يُعاد التحميل (سياسة عدم سبام الخادم).
- **أوفلاين**: كل أزرار الإعلانات تختفي فورًا (في القائمة والمتجر وشاشة الموت) وتعود تلقائيًا مع الاتصال.

سياسة عدم الإزعاج (مبنية في كود اللعبة)

| النوع | متى يظهر | الحماية |
|---|---|---|
| مكافأة Rewarded | فقط بضغطة اللاعب (هدية 🎁 / عملات المتجر 🎁 / إحياء) | اختياري دائماً + مؤقّت أمان 20 ث |
| بيني Interstitial | بعد نهاية الجولة | كل 4 جولات فقط + فاصل دقيقتين على الأقل + لا يظهر بعد إحياء |
| بانر Banner | جميع شاشات اللعبة، بما فيها اللعب والقائمة والصفحات الكاملة | يبقى مطلوبًا ولا يستدعي التطبيق `hideBanner`; قد لا يظهر محتوى إذا أعاد Unity `no fill` |

- مفتاح **المكافآت الإعلانية** في الإعدادات يوقف الإعلانات المكافئة والبينية؛ لا يخفي البانر الدائم.
- الـ Game ID (`800443610`) مدموج في كود اللعبة، ويمكن تجاوزه عبر `window.UnityAdsGameId`، ووضع الاختبار عبر `window.UnityAdsTestMode` (افتراضياً: إنتاج).
- للتحقق من التكامل، استخدم `window.UnityAdsTestMode=true` في **بناء اختباري فقط**. لا تنشر نسخة وضع الاختبار. عند وضع الإنتاج، راجع تفعيل موضع `Banner_Android` في لوحة Unity ورسالة `Banner` في التشخيص؛ `no fill` تعني أن Unity لم يقدّم إعلانًا في تلك المحاولة.
- لا يوجد أي مفتاح API سرّي — Game ID ليس سراً.

## أطوار الجرافيكس الثلاثة (بسيط / متوسط / خارق)

في الإعدادات ← **جرافيكس** ثلاثة أزرار. حفظ الاختيار تلقائي في `localStorage`، وهناك ترحيل تلقائي من الإعداد القديم «أداء منخفض» إلى «بسيط».

| الخاصية | بسيط (0) | متوسط (1) | خارق (2) |
|---|---|---|---|
| Tone mapping | بلا | بلا | **ACES Filmic** + تعريض 1.25 (ألوان سينمائية) |
| كثافة البكسل (Pixel Ratio) | 0.85 | حتى 2× | **حتى 3×** (أقصى حدّة) |
| الظلال | معطّلة | خريطة 1024 | **خريطة 2048** (أدقّ الظلال) |
| ضباب السماء/الجسيمات | 40 عقدة | 100 عقدة | **140 عقدة** |
| إضاءة أطراف زرقاء (Rim) | — | — | ✔ 0x9ec8ff |
| هالة الشمس (Additive Glow) | — | — | ✔ حجم 42 |
| ظل الطائر المتحرك على الأرض | — | — | ✔ يجتمع ويضمحل مع الارتفاع |
| الحلقات الذهبية | مطفأة الإشعاع | مطفأة الإشعاع | **إشعاع ذهبي 0x7a5200** |
| الجسيمات عند الأحداث | نصف العدد | العدد الكامل | **العدد + 3** |

- **مراقب الإطارات (FPS Watchdog)**: إذا انخفض المعدل عن 38 إطارًا لثلاث ثوانٍ أثناء اللعب يُخفَّض الطور تلقائيًا درجة واحدة (خارق←متوسط←بسيط) مع رسالة «تم تخفيض الجرافيكس تلقائيًا للحفاظ على السلاسة» — ولا يعمل على طور بسيط أبدًا.
- الفروق بين الأطوار حقيقية وليست تجميلية: كل عناصر المشهد تُعاد موادها (`needsUpdate`) بعد التبديل.

## ملاحظات أمنية ونشر

- تأكد أن Protobuf 3.25.6+ يأتي كتركيبة تبعية SDK (توصية أمنية من Unity).
- **Test mode ON** أثناء التجربة، **OFF** قبل رفع الإصدار إلى Google Play.
- إن رغبت لاحقاً بالوساطة (AdMob + Meta + غيرها) فالحل Unity LevelPlay — الحاجة وقتها تغيير الإضافة الأصلية فقط؛ واجهة اللعبة (JS) لن تتغير.
